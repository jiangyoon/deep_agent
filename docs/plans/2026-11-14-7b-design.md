# 7B-1 后端身份与隔离设计

用户已确认：用 Python 脚本手动创建用户；登录有效期为 7 天；不迁移旧数据。

## 方案

采用 SQLite 服务端 Session + 随机 Cookie 凭证。相较 JWT，退出可以立即撤销；相较仅签名 Cookie，数据库能管理有效期并撤销凭证。保持现有 SQLite 技术栈，不增加依赖。

`data/users.db` 保存 users、auth_sessions、chat_sessions。密码用标准库 PBKDF2-HMAC-SHA256（600000 次）加盐哈希；登录凭证用 secrets 生成，数据库只存 SHA-256 摘要。Cookie 为 HttpOnly、SameSite=Lax、Path=/、7 天；本机 HTTP 默认不启用 Secure，HTTPS 部署可配置启用。写接口拒绝跨源 Origin 和跨站 Fetch Metadata。

聊天会话在创建时保存 user_id；列表、读取、继续、删除先在存储层按当前用户查找。不存在和无权限统一返回 404；未登录返回 401。删除期间通过会话锁避免与正在生成的请求冲突。早期无会话问答接口移除，避免留下另一条入口。

长期记忆按服务端解析的 user_id 划分 namespace；Web Agent 不接受客户端提交的 user_id。现有终端学习入口保留独立的本地记忆分组，不读取 Web 用户记忆。会话检查点继续由 sessions.db 保存。前端真实登录、跳转和过期处理属于 7B-2，本次不改页面。

## 文件与验证

新增 core/user_store.py、web/auth.py、manage_users.py、tests/；修改 Web 路由、Agent/backend 组装和记忆存储。用临时 SQLite 库验证创建用户、密码校验、登录/退出/过期、Cookie 属性、跨源请求、两用户会话和记忆隔离、重启恢复。无需联网模型的测试使用框架自带的假模型或替身；不发送真实对话或读取本地密钥。
