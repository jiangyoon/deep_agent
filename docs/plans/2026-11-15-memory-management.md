# 当前用户记忆管理设计与实施计划

**Goal:** 完成用户已要求的记忆查看、全文编辑、保存、取消和清空；其他增强功能不做。

**Architecture:** 在现有聊天页打开记忆对话框，操作当前用户的 `/memories/AGENTS.md`。复用登录校验和记忆 namespace；GET 返回正文、内容长度、更新时间和版本指纹，PUT/DELETE 携带读取时的指纹。更新复用生成运行锁，拒绝忙时写入，比较指纹以避免覆盖其他页面或 Agent 的更新。清空后恢复空模板，保证后续 edit_file 可用。

**Tech Stack:** 现有 FastAPI、SqliteStore、Vue 3；hashlib 生成指纹；unittest 与 Node 内置测试，不增加依赖。

选择页面内对话框，保持当前会话位置；独立记忆页面需要额外导航，本轮不采用。全文编辑沿用已有 Markdown 文本格式，不做条目化、版本历史、导入导出。

## 实施步骤

1. 先写接口测试并确认失败：未登录拒绝、用户隔离、初始为空、保存和持久化、过期指纹拒绝、清空恢复模板、生成中禁止修改。
2. core/memory_store.py 增加当前记忆快照（内容、指纹、长度和更新时间），沿用现有读写函数。
3. web/app.py 增加 GET/PUT/DELETE /api/memory，更新时使用当前用户身份、指纹校验及现有运行锁。
4. 先写页面行为测试并确认失败，再把侧栏记忆按钮接入对话框，实现加载、编辑、保存、取消、清空二次确认、失败时保留草稿、重新加载确认。
5. 提示旧会话可能继续使用原检查点中的记忆，新会话稳定使用新内容；清空不删除历史聊天。
6. 运行全部 Python/Node 测试、编译和 JavaScript 语法检查，独立评审并同步交接文档。

## 验收

- 当前用户只管理自己的记忆，输入 user_id 不得改变身份。
- 手动更新不覆盖用户打开窗口之后发生的变化；忙和冲突均返回明确提示。
- 取消或写入失败不改数据库；清空可取消，确认后恢复模板。
- 不安装依赖、不读取真实记忆、不发送真实模型请求、不改其他会话增强功能。
