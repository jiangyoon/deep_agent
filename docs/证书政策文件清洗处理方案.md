### 2.3 核心决策：哪些向量查询，哪些结构化查询

本方案采用四种去向：**V＝向量与关键词联合检索；S＝结构化字段查询；F＝原件/附件及目录；H＝历史、待核实或排除区，不进入默认检索。** V和S可以同时存在，它们是两种查询方式，不是同一份原文被当成两项独立证据。向量、正文及结构化表是否部署在同一个数据库，另行确定。

| 材料/数据 | 对应文件ID | 查询方式 | 实际存什么 | 典型查询 |
|---|---|---|---|---|
| 公司办法、申报条件、北京/河北评审政策 | N001、N003、N007、N019、N020、N022、N028、N029、N035 | **V为主**，按地区、渠道、专业、职级等元数据过滤 | 完整条款原文、层级、来源定位、适用范围，以及检索片段的向量；首版不抽成完整可执行资格规则 | “本科机械工程、工作5年、一建，申报高工还需要什么条件？” |
| 年度申报通知 | N006、N021、N023、N044 | **V＋S** | 全文条款及向量；另外提取申报批次、报名截止日、材料截止日、资历计算日等时间事项 | V解释当年要求，S查某批次的报名时间；不能用一个日期代替全部截止日 |
| 证书奖励目录 | N033、N034 | **S为主，V辅助解释** | 奖励记录、金额与周期、附加条件、组合奖励、共享规则；同源文本生成向量用于模糊找证书及解释限制 | “哪些证书有注册补贴？”用S筛选；“为什么这个证书不能领？”结合V取条件 |
| 国内及国际资格与职称对应表 | N017、N018、N024、N025 | **S为主，V辅助解释** | 资格名称/级别、对应职称、取得时间限制、适用范围及原文条件；同时保留可检索文本 | “一级建造师对应什么职称？”先查记录，再返回全部附加条件 |
| 河北职称专业目录 | N030 | **S为主**，名称/别名匹配；不单独向量化目录行 | 系列、专业、职级、名称层级、对应汇编子文档ID；不存在或未知的信息不补造 | “河北有哪些工程专业？”“机械相关条件在哪份子文档？” |
| 材料要求、论文要求、员工操作手册 | N008、N013、N036、N039、N041 | **V＋F** | 步骤与材料清单正文及向量；关联模板ID、截图和原件路径。原件和截图本身不直接生成通用文本向量 | “高工预报名怎么操作？”“论文和材料要怎么准备？” |
| 培训攻略、渠道简介 | N026、N027、N031、N032 | 核验通过的部分进入**V参考解读层**；有差异的部分进入H | 按主题/路径分支保存解读文本，标记其性质并关联正式来源；不直接抽成自动资格规则 | “有哪些职称取得渠道？”找解读；具体资格结论继续查正式政策 |
| 评审表、承诺书、证明、推荐书、汇总表 | N004、N005、N009—N012、N014—N016、N037、N038、N040 | **F＋主文件附件关联**；不做独立内容检索 | 原文件、附件名称、格式、大小、哈希及其与主通知具体版本的关联；不解析附件正文，不生成知识块或向量 | 命中对应主通知后，带出该版本的可下载附件列表 |
| 修订对比表 | N002 | **H**，可按文档/版本查阅，首版不建默认向量 | 原件、新旧列、变更说明和关联文档；标题异常待确认 | 需要核查历史差异时按ID查看，不默认拿旧条款回答 |
| 专家名单、减负评估表 | N042、N043 | **H/F**；无通用向量及业务查询接口 | 专家名单受限保留；行政表归档。员工编号和姓名不进入问答索引 | 不支持通用聊天查询专家个人信息 |

### 2.4 结构化数据的具体边界

以下是首版明确拟落为结构化记录的数据，JSONL只是导入格式，发布后由数据库字段或关联表承载，支持筛选和精确查询。

| 记录类型 | 最少字段 | 需保留的关联/逻辑 |
|---|---|---|
| 证书名称及别名 | 证书ID、原名、规范名、别名、级别、专业方向、来源 | 别名仅在确认同义时关联，不能把不同证书合并 |
| 奖励明细 | 证书/组合ID、奖励类型、级别、金额、币种、周期、上限、奖励假、适用时间、原文条件 | 单证、多证、报销、年度专项分类型；空值、无、未说明分别保存 |
| 组合及共享条件 | 条件ID、条件原文、条件类型、逻辑分组、关联奖励ID、来源 | 保存AND/OR、可选组合、互斥/只能领取一次等明确关系；不能确定的逻辑标记待核实，查询结果必须带回关联条件 |
| 职称对应关系 | 证书ID/级别、对应职称系列/级别、地区、取得时间限制、附加条件、依据 | 对应关系不代表满足全部申报条件；一个证书可有多条带不同适用范围的记录 |
| 年度事项 | 通知ID、地区/渠道、批次、事件类型、起止日期、精度、确定性、日期原文 | 预计日期、月份区间、另行通知不能转换成虚构的精确日期；年限计算日与报名日分开 |
| 专业目录 | 目录ID、系列、专业名称、职级、父级ID、对应政策子文档ID | 目录用于导航和过滤，不从目录推断学历、年限条件 |
| 来源及附件关联 | 文档/版本/附件ID、名称、类型、哈希、原件位置、适用范围、主文附件关系、核验状态 | 附件元信息仅用于关联和下载，不是模板正文的结构化入库；来源关系支持V/S结果回溯 |

**首版不结构化为自动判定规则的内容**：完整申报资格中的学历、资历、工作经历、社保、业绩、破格、例外及其跨条款依赖。它们保留正式条文，通过V取回后由Agent结合员工情况解释。若后续要求系统自动算出“最早哪年符合资格”，需另行设计条件表达式、时间计算及人工核验，不能只抽出“本科/5年”两列就声称已支持。

## 3. 各类材料如何处理

### 3.1 公司制度、申报条件及年度通知

**处理对象**：管理办法、印发通知、220号和244号通知、工程师及高级工程师条件、论文要求和材料上报要求。

**处理方法**：

1. 按原顺序提取段落和表格，恢复章、条、款及列表编号。表格中的重复合并单元格只保留其实际含义。
2. 区分政策正文、解释说明和附带模板；保留材料名称及填写要求，空白表格壳不进入政策正文。
3. 按完整条款或材料准备事项组织内容，不把“符合以下条件之一”“满足其中三项”等引导句与条件列表拆开。
4. 年度通知分别提取申报批次、报名时间、年限计算截止日和材料提交时间，不能合并成一个“截止日期”。“预计”“另行通知”等原有限定必须保留。
5. 关联印发通知、办法正文及附件。文号引用不一致时，原文保留，增加别名或待核对标记，不擅自改正文号。

**产物**：带章节、来源定位及附件关系的政策Markdown；按完整条款组织的检索记录；年度时间事项清单。

### 3.2 北京政策和资格与职称对应表

**处理方法**：

- 管理办法、年度通知、海淀通知及人工智能专业政策分别保存，不能把区级要求或专业专项条件推广为北京市通用条件。
- 两份国内资格对应PDF逐项比对证书、级别、取得时间和附注；相同内容只建一套检索记录，差异部分保留来源等待核对。
- 国际对应表PDF与XLSX比对后，优先利用XLSX恢复表格结构；只有确认对应版本和内容一致后才合并检索来源。
- 每条对应记录保存证书名称、资格级别、可对应职称、适用时间及附加条件、依据和原表位置。
- 保留“可聘”“对应”“视同”等原用语，不统一改成“自动取得职称”或“必然可以申报高一级”。

**产物**：北京政策正文、对应关系JSONL及其自然语言知识块、跨载体差异清单。

### 3.3 河北上下册汇编和专业目录

**处理方法**：

1. 提取目录，建立“系列—专业—职级—PDF起止页”的映射，再根据正文标题验证边界。
2. 以某专业某职级的一份评审条件作为独立子文档，随后按条款切分；不是按固定页数切割整本PDF。
3. 修复断行、目录装饰码及全角数字，区分PDF物理页和印刷页。保留原文与规范化文本，禁止删去条件中的数字或单位。
4. 首批专业待用户确认。机械工程背景案例需要覆盖哪些目标专业，应由资料和业务范围确认，不能将学历专业直接等同于申报专业。
5. 未选入首批的专业保留目录及原件，不宣称已能回答；检索不到时可以按已约定的外部查询工具补充查证。

**产物**：专业目录索引、按专业职级拆分的政策Markdown及检索记录、待核对的版本信息。

### 3.4 证书奖励目录：XLSX与新增Markdown

**处理方法**：

- 以XLSX的单元格、合并关系和字体为转录核验依据，复用MD的文字表达；二者不能作为两份独立政策重复入库。
- 将MD中的“同上”解析为明确内容，核对是否来自真正的合并区域。空白、“无”“——”分别保留原状态，不统一填写为零。
- 将蓝色字体表达的含义转成字段及文字说明，并核对主题色和适用范围。组合奖励中某个名称着色，不能直接推广为组合内所有证书均可对应职称。
- 分开整理单证奖励、一人多证奖励、考试费报销和年度专项奖励，保留“且”“或”、替代组合及只能申请一次等关系。
- 对奖励级别映射金额、奖励假，保存映射依据；注册补贴、使用补贴保留月/年单位和上限。
- 全表说明、共享限制与具体记录建立关联。证书样例图片保留为附件，图片公式不进入语义正文。
- 2025年目录是否继续有效待资料方确认。其中年度专项奖励明确限制为2025年，不能直接用于2026年奖励建议，也不能因此将整个目录全部判为失效。

**产物**：规范奖励Markdown、奖励记录JSONL、共享规则清单、对应Excel位置及待确认事项。

结构化字段建议为：`证书原名、专业方向、奖励类型、级别/金额、奖励假、注册补贴及周期、使用补贴及周期、组合要求、附加条件、排除条件、时间范围、原文位置`。它们用于查询与引用，不自动触发奖励资格审批。

### 3.5 培训攻略和职称渠道简介

**处理方法**：

- 两份新增MD分别与PPTX、路径图核对，核验通过后优先使用MD，不再重新转录相同内容。
- 保留学历、渠道、职级和分支关系；合并相同建议，但不同渠道要求不能合并为统一条件。
- 对“考过即获”“不受年限限制”“无法晋升正高”“通过率高低”“专业相关度超过50%”等影响建议的表述，查找对应正式依据；未找到时标为待核实，不生成已确认的资格规则。
- 培训中包含的信息通信与土建范围，需要区分公司中级评审和集团高级评审；二者不必然是同一个适用范围，不能只因文字不同就直接改写。

## 4. 统一处理流程与产物

拟执行流程如下，当前只提交本方案供确认：

```text
登记原件与哈希
  → 按文件及内部章节分类，标记排除内容
  → 对照新增MD，解析正文/表格/图像
  → 恢复结构，清理版式噪声
  → 比对重复、版本、解读差异
  → 补充有依据的元数据，未知值保留未知
  → 形成知识文档与结构化记录
  → 质量复核、标记待确认内容
  → 生成发布范围内的检索片段及Embedding
```

### 4.1 输出组织

| 输出 | 格式 | 内容 |
|---|---|---|
| 原件清单 | JSON/CSV | 文档ID、批次、原路径、SHA256、载体关系、处理状态 |
| 政策、流程、参考解读 | Markdown＋元数据JSON | 保留章节和原文关系；三类分开标记 |
| 证书奖励、职称对应关系 | JSONL | 每条完整记录一行，保留共同条件及来源；同时生成供RAG使用的文本 |
| 检索数据 | JSONL，后续导入知识库 | 知识块ID、正文、元数据、父条款和来源定位；向量由客户Embedding生成 |
| 附件清单及关联 | 文件元信息＋关系记录 | 主文件版本ID、附件ID、名称、序号、用途、下载权限和文件位置；不含解析后的模板正文 |
| 排除、重复、冲突和缺失清单 | Markdown/CSV | 处理理由、关联文件、待决定问题，不把待核实内容伪装为已确认结论 |

以上是处理成果的格式约定，不意味着人工逐份重写全部材料，也不意味着已选定数据库。后续数据库应能承载这些记录并保持来源关联。

### 4.2 知识块元数据

| 字段 | 要求 |
|---|---|
| `source_id / source_hash` | 指向批次清单中的原件 |
| `source_locator` | PDF物理页/印刷页/条款；DOCX章节、段落或表格；Excel工作表及单元格；MD标题路径 |
| `material_type` | 正式政策、年度通知、对应表、奖励目录、操作指引、参考解读 |
| `organization / region / channel` | 公司/集团、北京/海淀/河北、认定/评审/考试；未知时不猜测 |
| `series / specialty / level` | 系列、专业、职级；非限定内容不强行加标签 |
| `policy_year / published_at / effective_at / expires_at` | 年度与日期分开，按原文填写；年度通知不等于其所有条款都在年底失效 |
| `verification_status` | 待核验、已核验、存在差异；与文件是否解析成功分开 |
| `parent_id / related_sources` | 条款上下文、主文与附件、全表说明、政策依据及版本关联 |

内部政策、外部政策和参考解读采用逻辑分层与来源标签即可，本方案不要求物理拆成多个数据库。文号不是唯一主键，同一文号的正文、附件及版本需要独立ID。

### 4.3 分块原则

- 先按业务结构分段，再根据客户Embedding输入长度控制大小；初步可用300—600个中文字符作普通段落试验值，不作为硬性切断线。
- 一个完整申报条件、附加要求及例外尽量一起保存。超长条款保留父条款，子块带上专业、职级和条件引导语。
- 奖励及对应表按完整记录切块，并携带关联的共同说明；跨多条的条件不能因切块丢失。
- 不将整张大表或整册PDF作为单一向量，也不为模板壳、姓名名单、图片公式生成通用检索向量。

### 4.4 查询时如何协同

以下为拟议的工具职责，工具名是示意，不是已实现接口；结构化查询使用受控参数，不让模型直接执行任意SQL。

| 工具职责 | 数据来源 | 返回内容 |
|---|---|---|
| `search_policy` | V政策/流程层，关键词与向量联合召回 | 完整条款或父条款上下文、适用范围、来源位置、核验状态 |
| `query_certificate_data` | S奖励、证书别名及职称对应记录 | 匹配记录、关联共同条件、金额单位、对应限制及来源；不只返回裸金额 |
| `query_policy_schedule` | S年度事项 | 指定地区、渠道、批次的事件和时间，保留预计/待通知状态 |
| `list_specialties` | S专业目录 | 专业列表和可检索政策范围，区分“目录已登记”和“正文已发布” |
| `get_document_attachments` | 主文件版本与附件关系＋F原件 | 按已定位的主通知版本返回附件名称、用途及经权限检查的下载入口；不检索模板正文 |

查询示例一：“机械工程本科，工作5年，已有一级建造师，想评高工”。先从记忆/追问了解地区、目标渠道及证书取得时间等；用S查一建职称对应关系，用V查该渠道和目标专业的高工条款；比较条件时保留缺少信息，不把工作5年直接当作持有中级5年。

查询示例二：“下一步考什么证书”。先明确目标；需要奖励比较时从S取得适用证书与金额、限制，再用V查询报考/职称政策；尚无报考条件依据的证书可通过WebSearch查证。不把奖励目录等同于报考资格目录，也不只按奖金排序作为职业建议。

### 4.5 报名附件的关联与下载

已按用户确认采用：**命中主通知后，通过外键关联返回其报名模板，供用户下载；模板正文不解析入知识库。** 不按“附件”二字一律排除知识内容。

| 附件性质 | 本批对象 | 处理 |
|---|---|---|
| 报名模板 | N004、N005、N009—N012、N014—N016、N037、N038、N040 | 仅文件存储、元信息登记和主通知版本关联；不解析正文、不切块、不向量化，也不做独立模板语义检索 |
| 知识性附件 | N007、N008、N013、N035、N039、N041等申报条件、材料要求和论文要求 | 正文仍按前述V政策/流程规则处理，同时可作为主通知附件下载；保留完整条件依据 |
| 人员或其他受限附件 | N042专家名单等 | 单独权限控制，不随主通知向所有用户默认返回 |

关系建议如下，字段为方案约定，尚未建表：

```text
document_versions（主文件版本）
    1 ── N document_attachments（关联记录）N ── 1 attachment_files（附件文件）
```

| 记录 | 最少字段 | 约束 |
|---|---|---|
| 附件文件 `attachment_files` | `id、storage_key、file_hash、file_type、file_size` | 同一内容可按哈希共享存储；文件本身不携带模板正文向量 |
| 主文件附件关系 `document_attachments` | `id、main_version_id、attachment_id、display_name、attachment_no、purpose、sort_order、download_policy` | 两个ID分别为主文件版本和附件文件的外键；名称/序号属于具体通知关系，允许同文件在不同主通知下有不同名称 |

关联到**具体版本**，防止新年度通知配上旧表。同一附件可挂到多份通知，不重复保存文件；完全相同的承诺书、证明也保留不同流程的关联。文件名和附件编号不作为唯一主键。

下载流程：检索命中政策条款 → 定位其所属主通知版本 → 查询附件关联 → 按权限和适用流程返回附件列表 → 用户点击下载。检索命中通用办法时，需先定位相关年度通知；年份或渠道不明确时先澄清，不直接返回任意年度模板。条款所属知识性附件也应能沿关系回到主通知。

N004—N016中上述模板归属220号通知N006；集团高工N037、N038、N040归属244号通知N044，具体序号及中间材料要求关系以原通知核对。给用户展示的是经后端授权的下载入口，不是服务器本地路径；文件替换产生新文件/关联版本，已发布主通知的附件关系不被无声覆盖。

本轮只生成上述文件元信息及关系，不将模板正文入库。“不解析入知识库”不免除发布前的文件安全、示例/真实个人信息和下载权限检查；必要时使用脱敏副本下载，原件仍受控保留。
