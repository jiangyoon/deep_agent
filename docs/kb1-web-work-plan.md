# KB1 网页问答实施计划

2026-11-19。首个里程碑是让员工在现有网页询问“一建在集团和北京分别对应什么”，获得两套有出处、能核对条件的回答。

## 1. 核实职称对应的默认查询范围

本次只读核对 PostgreSQL，现有 44 个来源、408 条正文、244 条对应、70 条奖励、17 条时间事项和 33 条附件关系。244 条对应全部标为 `review_ready`。用户确认 CFA 特许金融分析师证书和数据管理工程师（高级）已核实，两项均可按北京人社渠道查询。验收覆盖两项国际对应和正常的北京、集团对应记录。

## 2. 跑通第一条网页问答

在 `career_agent/knowledge/` 复用现有别名和对应查询逻辑，通过限定参数的只读工具接到 Web Agent。业务表显式使用 `public` schema，登录身份由后端传入。查询对应表和来源表，返回渠道、证书、对应职称、适用条件、文件名和原件位置。

从已登录网页输入里程碑问题，用实际模型验证“一建”的归一化、两个渠道各自的条件和引用。分别留存工具参数、命中记录和最终回答，便于判断错误发生在查询还是回答环节。

## 3. 接通政策原文与多轮资格咨询

先在 PostgreSQL 按处理状态、有效性及已知渠道、地区、年度、资料类型筛选来源，年度查询兼顾适用的常设办法。两路 Milvus 检索使用同一来源清单。合并、重排后按条款 ID 和来源 ID 回查 PostgreSQL 完整原文及定位。来源为空时返回资料缺口。

验收从“我本科机械工程，工作 5 年，有一建，想评高工”开始，不预填渠道或文件编号。观察 Agent 能否追问渠道、区分总工龄与取得前置职称后的年限，并随员工补充的信息调整查询。证据不足时补查或说明缺口。按方案先试每轮最多三次检索，记录调用次数、耗时、有效引用及停止原因，再决定正式预算。

## 4. 补齐奖励、时间、文号和附件

- 奖励按专业、金额、周期、组合条件及同来源目录共用说明回答。用“一建机电奖励多少”验收，明确目录年度及沿用情况。按 `blue_display_names` 渲染名称颜色。
- 时间按年度和事项类型核对。用“集团高工什么时候截止”验收，分别标明报名、材料提交和资历计算的时间，保留原文的预计措辞。
- 文号先定位印发通知，再沿知识性附件关系查办法正文。用“182 号怎么规定”验收引用是否落到具体条款。
- 报名模板从已定位的主通知列出。通过已登录的下载接口验证文件权限、附件版本和实际可下载性。

## 5. 首版验收与资料补充

复测同一员工跨轮、跨会话复用已确认的信息，修改记忆后使用新值，并用第二个账号验证隔离。对河北专业条件、正式报销流程和仅见于截图的操作步骤，验收系统能否说明证据缺口。

资料准备可并行推进。河北先处理目录，再按优先专业处理上下册汇编；培训攻略和渠道简介按咨询频率排期。向资料方核实正式报销流程。客户 WebSearch 接口在来源和联网条件明确后接入。
