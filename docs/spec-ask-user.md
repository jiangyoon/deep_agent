# 网页问答中的 Ask 弹窗

来源为本次对话中提出的“在模型回答问题时弹窗 ask”，沿用[证书咨询首版范围](intent-certificate-consultation.md)。2026-11-25，v1 评审稿。

风险等级暂定为低。Ask 只收集完成咨询所需的信息，结果仍用于政策答复和建议。

## Problem Statement

员工问“有一建，能评高工吗？”时，申报渠道可能决定应查哪套政策。当前网页可以展示模型输出的追问，员工需在输入框里另发一条消息。Ask 提供一个明确的填写入口，提交后接着处理原问题。

## Interaction

1. **发起提问。** Agent 从本轮、前文和已查资料中确认已知条件。确实缺少会改变下一步的信息时，提出一个具体问题。已知渠道或日期时直接沿用。
2. **暂停并弹窗。** 当前回答停在 Ask 步骤，标题显示“等待你回答”。弹窗显示问题、选项或输入框，以及“继续”和“暂不回答”。同一轮此前的思考、工具记录和正文仍可查看。
3. **提交后继续。** 有效回答被接收后，弹窗关闭，Ask 卡片收起，标题显示“已回答”。Agent 根据提交的信息继续查询和输出，结果追加到原回答。展开 Ask 卡片可回看问题和选择。
4. **返回或刷新。** 关闭弹窗只返回聊天页，可以从“等待你回答”的卡片重新打开。同一账号刷新或切回会话后，页面恢复待答卡片，已执行步骤仍在。
5. **暂不回答。** 【待确认】把跳过记录到同一轮，Agent 用已核实的资料继续，交代哪些结论还取决于缺少的信息。“还不确定”也是有效回答，按同一原则处理。

### 弹窗示例

员工问“有一建，能评高工吗？”且前文没有申报渠道，弹窗可显示：

> **你打算走哪个申报渠道？**  
> ○ 集团内部  
> ○ 公司内部  
> ○ 北京人社  
> ○ 其他地方人社  
> ○ 还不确定  
>
> **继续**　暂不回答

选“集团内部”后查集团政策。选“其他地方人社”且当前会话没有省市时，可以接着问“你准备在哪个省市申报？”。人事认可的资历起算日可以用文本填写。

## Business Rules

| 编号 | 规则 | 正例 | 边界示例 |
| --- | --- | --- | --- |
| BR-1 | 缺少会改变检索或判断的信息，且前文和现有资料无法补齐时才弹窗。 | “有一建，能评高工吗？”并且渠道未知，询问渠道。 | “有一建，能报集团高工吗？”已说明渠道，直接查集团政策。 |
| BR-2 | 政策事实由资料查证，员工个人事实由员工补充。 | 查过集团政策仍缺个人认可日期时，请员工核实人事认定的起算日。 | 预报名截止日属于政策事实，应查通知。 |
| BR-3 | 【待确认】首版同一会话同时只显示一个待答问题，每题使用单选或文本输入。 | 员工选了其他地方人社后，再问省市。 | 空白文本或尚未选择时，保留问题并提示填写。 |
| BR-4 | 每条答案只处理一次，绑定到当前待答问题。 | 提交“集团内部”后继续原回答。 | 双击提交只继续一次。用旧弹窗提交时提示该问题已处理或已变化。 |

## Acceptance Criteria

- [ ] 给定渠道未知的高工问题，当 Agent 发起 Ask，则本轮暂停，弹出一个渠道问题。提交“集团内部”后，首次涉及渠道的政策查询使用集团内部，正文继续出现在原回答。
- [ ] 给定“有一建，能报集团高工吗？”，当 Agent 处理时，则直接按集团渠道查证，不再弹窗确认渠道。
- [ ] 给定正在等待回答，当同一账号刷新或切回会话，则看见一张待答卡片，可以重新打开并提交。已完成的工具步骤可展开回看。
- [ ] 给定已发起 Ask，当用户仅关闭弹窗，则该轮仍等待，可以重新打开。选择“暂不回答”后，Agent 接着给已有依据支持的答复，并标出待核实的条件。
- [ ] 给定同一问题的两次提交，当服务端接收时，则最多恢复执行一次。给定其他账号尝试提交，则无法查看该问题或恢复会话。
- [ ] 给定提交遇到网络中断，当用户重新打开会话，则看到服务端已有的状态。仍待答时可以重试，已接收时能看到已回答状态。

**验收标准**为上述六项全部通过。用知识库里的集团案例核验渠道处理，用刷新、双重提交、断网恢复和双账号核验会话行为。

## 数据与权限

只有会话所属的登录账号可以查看、回答或跳过 Ask。选项和文本作为本轮会话记录保存，刷新后可回看。考虑到资历日期可能涉及员工个人信息，弹窗只收集当前判断所需的内容，普通服务日志只记提交状态。尚无额外导出入口。

## 外部依赖与异常

| 依赖 | 异常时的表现 |
| --- | --- |
| 会话状态服务 | 状态加载或提交失败时显示重试提示。收到确认前不显示“已回答”。 |
| 问答模型或政策查询服务 | 用户答复已接收但继续生成失败时，展示已提交的答案及本轮错误。可以重试继续，不要求用户重复填写。 |

## 人工确认点

员工确认自己的渠道、地区或资历事实。Agent 根据答复给出政策咨询，申报资格的正式认定仍由相应部门作出。

## Non-Goals

后续版本再考虑多题表单、多选与附件上传。Ask 的回答默认只作为本次会话上下文，长期记忆仍通过现有流程单独确认。

## 待确认清单

1. 首版每次只问一题，输入形态为单选或文本。
2. “暂不回答”后，允许 Agent 给出有依据的阶段性答复，并说明还缺什么。
